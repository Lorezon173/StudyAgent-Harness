## 2. 为什么会做这项工作

项目已有掌握度图谱：教学协作环会更新节点的掌握度、最后练习时间、练习次数和评分依据。B-② 的目标是在不干扰教学记录的前提下，在用户主动请求时按时间计算“当前投影掌握度”，并生成复习建议。

用户的不可推翻要求是：

- 用户可开关；
- 参数可调；
- 可主动调用；
- 不强制、也不隐式自动触发。

初版 B-② Spec 错将旧 aiosqlite 图谱/画像路径当成生产数据源，还包含 Celery、事件、Curator 改动等范围膨胀内容；已被本窗口修订为新栈 SQLAlchemy 的只读、手动 MVP。

## 3. 已核实的当前系统事实

### 3.1 掌握度当前如何工作

- 生产新栈 chat 与 stream chat 会以 SQLAlchemy store 加载 `MasteryGraph`。
- 同步协作环中 Curator 在内存中更新节点。
- 会话结束后，API 将图通过 `persist_turn()` 与消息、会话一起提交到 SQLAlchemy 表。
- profile API 读取同一 SQLAlchemy `mastery_nodes` 计算平均掌握度。

因此，B-② Review 必须读取 SQLAlchemy `mastery_nodes` / `mastery_edges`，不应读取旧 aiosqlite 文件。

### 3.2 被排除的旧路径

旧 `MasteryGraphStore` 是单独的 aiosqlite 数据库，包含同名 mastery 表与 `user_profile_l3`。它主要服务旧 UserProfile 和测试；新栈 API 不应接入它，B-② 也不应修改、桥接或迁移它。

### 3.3 Feature Flag 的现实约束

只有 `FEATURE_USE_NEW_AGENT_GRAPH=true` 时，新栈 chat/chat_stream 才会写 SQLAlchemy 掌握图。flag 未设置或不是真值时默认走 legacy 路径，legacy 不写这套 mastery 表。

本窗口已确认的产品策略：

> **Review 严格仅服务新栈。**
> 当 `FEATURE_USE_NEW_AGENT_GRAPH` 未开启时，所有 `/api/review/*` 必须返回明确的“新栈掌握度路径未启用”受控错误；不改 legacy、不桥接旧数据、不以空数组伪装功能正常。

## 4. 已完成的设计修订

### 4.1 已确定且应保留的 MVP 边界

- 使用 SQLAlchemy 掌握图作为唯一事实源。
- 新建 SQLAlchemy `review_preferences` 偏好表和 store。
- 提供用户主动 API：偏好 GET/PUT、建议 trigger POST。
- 衰减为请求时只读投影：绝不写回 mastery。
- 不调用 `MasteryGraph.update_mastery()` 做衰减，因为该方法会改写最后练习时间并增加练习次数。
- 支持指数半衰期、线性、阶梯三种曲线。
- 冷启动节点（无最后练习时间）不进入“逾期复习”建议。
- 不做 Celery、后台任务、定时提醒、事件总线、Curator 改动、复习内容生成、UI。

### 4.2 已修复的数学与语义问题

- 指数衰减使用真半衰期：`initial × 2 ** (-t_days / half_life)`。
- 固定验收例：80 分、7 天、半衰期 7 天，结果约 40 分。
- interval 采用严格 `>`：恰好等于 `interval_days` 时不命中。
- `priority_score` 小者优先；同分以 `topic_id` 作为稳定 tie-break。
- 若候选项的已练习前置知识薄弱，加入原因并给固定 -10 priority penalty。

### 4.3 独立 review 发现并已写回的两个有效问题

#### A. Alembic 历史迁移链缺口

当前 Alembic 链中，后续 M3 migration 会操作 `mastery_nodes` / `mastery_edges`，但其此前没有迁移创建这两张表。SQLite 的运行时 `create_all()` 可掩盖这个问题，PostgreSQL 不会。

已在 Spec/Todo 中升级为 **B2.0 阻断性交付**：

- 修复历史 mastery 表创建责任；
- 在干净 PostgreSQL 上验证 `alembic upgrade head`；
- 验证两表先创建、再允许 M3 后续操作，且结构与 ORM 一致；
- 只有修复后，才能新增 review preference migration。

注意：Spec 刻意没有预设具体迁移技巧（例如插入旧 revision 或重写迁移），以免在没验证部署历史前伪造正确方案；实施前需进一步选择兼容方案。

#### B. Feature Flag rollout 缺口

已写入严格新栈策略与测试要求。Review router 在访问偏好、图或计算建议之前必须检查 flag；关闭时受控拒绝。
