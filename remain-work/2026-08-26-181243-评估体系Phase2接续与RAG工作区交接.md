## 4. 关键决策与边界

### 已确认决策
- 混合方案分工：Retriever 检索质量使用 RAGAS；Tutor 教学质量计划使用 DeepEval G-Eval；详细决策与否决项见主 spec。
- RAGAS / DeepEval 仅属于 L2 旁路评估，不得放进在线 `handle()` 热路径；实现边界见主 spec。
- judge 必须与被评 Agent 不同族；当前 `build_judge()` 已在构造期执行校验。
- RAGAS 不可用、judge 不可用、缺必要黄金数据或评估异常时，应显式降级而非伪造语义分数；具体降级语义见主 spec。
- Phase 4 中真实检索评估需使用 pgvector；非 pgvector rerun 应显式 degraded，而非拿 fake 检索结果伪装为真实评估。

### 明确不要做的事
- 不要把 DeepEval/RAGAS 接入在线 Agent `handle()` 路径。
- 不要因为当前有 `scripts/generate_ragas_testset.py` 就跳过 API spike / happy-path 验证。
- 不要将未确认来源的工作区改动、图片、缓存或 `.playwright-mcp/` 与评估代码一起提交。
- 不要假定 `EvalStore` 已经落库；当前代码是内存 LRU 存储。
- 不要假定 `rerun_eval` 已经实际跑 benchmark；当前实现仍是 stub。
- 不要使用 `git commit --amend`、`git add -A` 或 `git add .`。

### 尚未验证、不能当作事实的点
- 当前未跟踪 Phase 2 脚本、候选 CSV、κ 校准脚本是否全部来自同一工作单元，是否已经过测试和独立 review。
- `spike_geval_compat.py` 是否真正证明 DeepEval 与项目 judge / 当前依赖版本兼容。
- `ragas_generated_candidates.csv` 是否为真实 RAGAS 结果还是 dry-run / 临时样本。
- 当前 `pyproject.toml` 的未提交改动是否引入 DeepEval 或仅属于并行 RAG 工作。
