# 后续需求：知识内容规划、可编辑权重与对话页画像缩略展示

日期：2026-10-23。来源：用户在确认纸感书房当前版本后提出的补充要求。本文是项目内待实施需求记录，不代表已接通全网检索、上传解析、权重计算或画像评估；不写入全局偏好。后续 spec 须追溯本文件及同目录 multi-session-profile-raw。

## 已明确的用户需求

- 问答页留出知识点画像的缩略展示，浓缩学习画像内容，说明当前知识点学习进展，可用百分比展示；本轮先提供多个视觉样式供参考。
- 知识点的内容范围和内容占比可由 LLM 根据知识内容规划和计算，默认由 LLM 完成。
- 用户可手动添加、修改知识内容，并设定内容篇幅及重要性占比。
- 规划来源支持网络及用户上传的文档；默认全网检索。
- 用户可以手动调整系统生成的内容与占比。
- 检索、上传内容处理、自动规划与手动编辑等功能放入后续计划，本轮仅记录，不实现。

## 第一层：模块总览

候选目标：在用户所属主题画像内形成一份可编辑、可追溯、有版本的知识规划，再基于评估证据展示学习状态。网络/文档资料进入规划，经 LLM 分解知识点和建议权重，用户可以修订；画像详情与问答缩略展示使用同一版本的数据来源。

沿用现有前后端与主题画像设计。全网检索是规划资料来源的默认选项，不等于当前已完成的在线检索能力，也不等于每次对话必定联网；具体检索时机与范围后续确认。不限定新的检索供应商、文档解析方案或模型服务。

## 第二层：子模块概述

### 资料来源与溯源

默认选择网络来源，也允许选择用户上传文档；是否允许两者混合、文档是否优先、检索语言与时间范围需后续确认。网络保留标题、URL、获取时间及支持相应知识点的段落依据；文档保留文件标识、版本、页码/段落与用户归属。无检索结果或解析失败需明确提示，不伪装为已检索内容。

### LLM 规划与人工编辑

LLM 输出候选知识点、内容范围、篇幅建议、重要性权重和理由。用户可添加/删除/修改知识点、修改篇幅和权重，改动保留版本。重新生成不得静默覆盖人工修改；如何锁定编辑字段、何时确认生效及重算需后续设计。

篇幅、内容覆盖占比、重要性权重与学习掌握度是不同概念。篇幅决定讲多少，重要性权重影响综合指标的贡献，掌握度由学习评估产生；不能因为内容篇幅短就判定不重要，也不能因为未涉及就推断已经掌握。

### 学习画像与缩略展示

缩略图使用完整画像的同源数据：当前主题、当前知识点、掌握度、待巩固要点及查看完整画像入口。支持环形进度、横向进度卡、分段知识路径等候选样式，本轮仅为演示。示例掌握度不冒充真实学习结果、内容权重或课程完成率。

未来若展示主题综合百分比，候选方案是按重要性归一后的权重汇总知识点掌握度；这仅是待确认计算方案。必须规定未评估知识点、用户修改权重、知识点增删、规划版本变化的处理方式，同时显示已评估覆盖率，避免一个高分知识点让主题看起来接近学完。

## 第三层：候选详细设计（供后续规划，无代码）

- collectPlanningSources：输入本人主题、来源选项和用户授权的文档引用，输出资料及来源元数据；验证文件所有权、处理检索/解析失败。
- proposeKnowledgePlan：输入主题范围、资料与已有规划，输出候选知识点、篇幅、内容占比、重要性建议与依据；无充分依据时标记不确定。
- editKnowledgePlan：输入规划版本、用户增删改操作及权重设置，输出待保存的新版本；校验负值、非法数值、重复节点及范围冲突。
- normalizeWeights：输入原始重要性权重及人工锁定范围，输出可比较的归一权重；总和为零、缺失值、舍入误差和锁定冲突需明示规则。篇幅与内容覆盖占比不能被此函数擅自覆盖。
- saveKnowledgePlan：输入身份、主题画像标识、版本和更改，输出保存后的版本；旧版本并发提交不得静默覆盖，保留人工与模型来源。
- summarizeLearningProgress：输入有效规划、对应评估证据及计算策略，输出知识点掌握度、主题综合指标和已评估覆盖率；未评估状态单列，不伪造进度。
- renderProgressPreview：输入当前会话所属画像的摘要和所选样式，输出问答页缩略展示；无评估数据展示“待评估”，查看详情打开同一主题画像。

候选字段：规划 id、user_id、profile_id、version、source_mode、sources、knowledge_nodes；知识点 id、标题、范围、父节点、estimated_length、length_unit、content_share、importance_weight、normalized_weight、来源引用、创建方式、人工修改/锁定字段；评估证据与掌握度独立存储并关联规划版本。上述字段不是已冻结接口。

## 后续验收关注点

1. 默认网络规划可追溯，文档规划能定位原文，不把模型常识冒充检索证据。
2. 用户修改篇幅、占比和重要性均可保存恢复；模型重算保留人工编辑，版本冲突可处理。
3. 权重校验与归一规则明确，不出现负权重、零总和误计算或百分比总和误导。
4. 不同用户/主题隔离；同主题会话引用同一有效规划及画像版本。
5. 问答缩略图和画像详情一致，明确区分掌握度、覆盖率、内容占比及重要性。
6. 未评估不伪造百分比；调整知识范围后指标变化有原因和版本依据。

## 待后续确认

内容篇幅采用字数、学习时长还是相对比例；内容占比与重要性是否分别编辑；主题综合进度如何处理未评估节点；网络与文档混合优先级；默认检索触发时机；人工调整的锁定和版本生效方式。这些在正式实现前补齐，不阻塞本轮样式预览。

补充当前知识点定位：正式会话需关联 active_knowledge_node_id 或等价的、可追溯的知识节点定位，才能在缩略展示中准确标出正在讨论的知识点。当前预览缺少该数据，展示主题总体与知识点列表，不将主题百分比当作当前单点进度。
