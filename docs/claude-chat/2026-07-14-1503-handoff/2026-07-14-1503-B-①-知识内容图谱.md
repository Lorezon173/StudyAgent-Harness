## 三、已核实事实与含义

### 1. 范围决策已确认

- 用户已明确选择 **A**：本轮修订 B-① spec 时，**纳入 RAG 主链前置缺口**，而不是只修图谱内部结构。

### 2. 当前 B-① spec 的关键已核实问题

仅列结论，不复述原文：

- 现有默认检索源行为与 B-① spec 对 `sources=None` / `sources="all"` 的描述不一致。
- 现有 `RetrieverAgent → RAGCoordinator → IndexProvider` 契约无法把 `local/global/hybrid` 作为外部可选模式透传。
- 现有 vector 写入已含 `user_id/scope`，但检索 SQL 未执行对应过滤。
- B-① 草案中 graph provider、vector provider、Coordinator 之间的“摄入所有权 / 融合所有权”边界不清，会导致重复写入或重复召回风险。
- 图谱关系表的键设计、关系相关性排序依据、global 检索路径、迁移前提等仍存在阻断项。
- fresh SQLite 的 Alembic 升级链当前已有既存问题，不能直接把“alembic upgrade + sqlite create_all”写成 B-① 的已成立验收路径。

### 3. 当前推荐的修订方向（已形成设计，但尚未落笔）

本窗口已收敛出一个待用户批准后写入 spec 的设计骨架：

- B-① 从“纯 graph provider 设计”升级为“图谱能力 + RAG 主链启用前置条件”
- 图谱数据域采用 `user_id + scope` 统一隔离
- 向量写入与图谱写入通过显式摄入编排 fan-out，避免 graph provider 隐式代写 vector
- `sources` 与 `retrieval_mode` 分离：前者表示调用哪些 provider，后者表示 `vector/local/global/hybrid` 的检索意图
- 跨 provider 融合归 `RAGCoordinator`，而不是 graph provider 内部再隐式调用 vector provider
- `GraphStore` 保持纯存储/查询职责，不在存储层隐式调用 LLM
- 固定权重、关系排序、LightRAG 具体能力映射、doc/chunk provenance 细节全部保留为 spike 后冻结项
