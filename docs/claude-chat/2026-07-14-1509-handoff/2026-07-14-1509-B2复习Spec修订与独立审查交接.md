## 2. 当前有效结论

### 2.1 已确认应保留的方向

- B-② 的复习推荐应以 **SQLAlchemy `mastery_nodes` / `mastery_edges`** 为唯一事实源。
- 不应再接旧 `MasteryGraphStore` / `user_profile_l3`。
- 衰减必须是**请求时只读投影**，不能写回 `mastery_nodes.mastery`。
- 不能调用 `MasteryGraph.update_mastery()` 来做“被动衰减”。
- 指数衰减应使用真半衰期表达。
- 冷启动节点不应被伪装成“逾期复习”。
- 本阶段不应引入 Celery、定时任务、事件、Curator 改动。

### 2.2 独立 review 后保留下来的问题

#### Blocker
需要把“历史 mastery 表 Alembic 迁移链修复”从单纯 gate 升级为 B-② 的明确交付项：
- 不是只写“先检查、失败再修”；
- 而是要在 spec 里写成具体子模块、迁移责任、结构验收和发布前验证项。

#### Major
需要补上 **Feature Flag 关闭时 review 能否可用** 的 rollout 契约：
- 当前只有新 Agent Graph 路径会写 SQLAlchemy mastery 数据；
- legacy 路径不会；
- 若不明确策略，review API 可能表面可用但实际上没有任何历史掌握度可读。

### 2.3 已被复核否决、不要继续扩大范围的问题

- **不要为了形式新增空壳 Orchestration 层。**
- **不要因为 trigger 返回 `[]` 就强行扩展为带诊断元数据的新响应对象。**

这两项在独立 verify 后都不构成当前 spec 的有效阻断。
