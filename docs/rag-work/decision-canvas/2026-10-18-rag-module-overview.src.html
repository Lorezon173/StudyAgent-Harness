从资料，到检索，再到教学使用

当前 RAG：
让教学回答有书可查，
还需完成真实闭环。

RAG 是“检索增强生成”：先从资料里找与问题相关的内容，再把找到的证据交给模型。当前仓库已有提取、切块、存储和检索等实现；真实单书摄入、20 题基线、在线 Tutor 消费证据，仍须分别验收。

为什么教学系统需要它？

用户可能问一本指定书的概念、论证或原文依据。模型自身知识无法证明回答来自这本书。RAG 把“从哪里找到的内容”作为可检查的输入，让教师 Agent 有机会结合教材解释，而不只依赖模型记忆。

贯穿例子：把一本 EPUB 用于回答，先提取和切块，再生成向量、写入索引、生成证明、跑 20 题检索，最后把当前轮证据交给 Tutor。前半已有基础代码；runner、强准入和线上闭环尚待接线；真实验收尚未完成。

但“找到了相关片段”还不等于“解释正确”。系统还必须处理权限、检索失败、错轮证据，以及模型是否实际消费了证据。这些正是当前修订计划要补齐的闭环。

先记住三个判断层次

代码存在：仓库能找到实现。

真实验收通过：用真实资产、真实依赖与可追溯证据验证完整链路。三者不能互相替代。

工作机制

四条链路分别回答四个问题

摄入解决“书怎样进入索引”，检索解决“问题怎样找到证据”，离线评测解决“检索质量与故障怎样被量化”，在线教学解决“证据怎样真正影响这一轮回答”。它们共享产品检索主链，但产物和验收职责不同。
