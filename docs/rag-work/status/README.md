# RAG Foundation 状态片段目录

> 目的：为四个并发窗口提供**各写各的状态片段**，避免多人直接同时编辑主清单引发冲突。  
> 主清单位置：[`../designs/2026-07-24-rag-foundation-parallel-todolist.md`](../designs/2026-07-24-rag-foundation-parallel-todolist.md)

## 协议

- 主清单是**单写者文档**：只允许主控窗口更新。
- 四个工作窗口分别只更新自己名下的状态片段：
  - `RAG-A.md`
  - `RAG-B.md`
  - `RAG-C.md`
  - `RAG-D.md`
- 工作窗口不得直接修改主清单。
- 主控窗口根据四个状态片段汇总状态、裁决冲突、冻结共享契约，并只在主清单写入汇总结论。

## 状态片段最小要求

每次更新都至少写清：

1. 当前结论
2. 已核实事实（含 `file:line`）
3. 不确定项 / 阻断项
4. 拟修改资产
5. 输入/输出契约
6. 方案对照与选择理由
7. 影响传播
8. 验证状态表
9. 测试矩阵
10. 需要主控冻结的共享契约
11. 未做事项

## 推荐流程

1. 工作窗口更新自己的状态片段；
2. 工作窗口在会话中向主控报告“状态片段已更新 + 关键变化摘要”；
3. 主控读取该状态片段并在主清单更新：状态、冲突、下一步；
4. 共享契约冻结后，主控再分发第二轮编码任务。

## 注意

- 如果某窗口需要修订共享契约，不要直接改主清单；请在自己的状态片段新增“请求主控冻结/修订”的小节。
- 如果多个窗口都发现同一冲突，分别写进各自状态片段，由主控统一裁决。
