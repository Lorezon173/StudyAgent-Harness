## 第一层：模块总览

目标：仍挂载的 Login 在统一 workspace account generation 改变时，立即失效旧提交并释放本地忙状态。用户可以在旧请求尚未结束时重新提交；旧请求任何成功、失败及 finally 都不能覆盖新认证、导航、错误或新提交的忙状态。

事实依据：独立真实组件探针使用 AuthProvider、MemoryRouter、Login、真实 apiGet/client/workspaceStore，仅 mock fetch。已有 A 身份进入登录页，提交 B；A 的当前受保护请求返回 401，AuthProvider 清身份并推进 generation；B 返回后旧 current() 正确拒绝认证副作用，但 finally 同样被拒绝，busyRef 和 busy 永久保留。原 62 项测试未覆盖此顺序。Dialog 关闭后的晚画像探针通过，不列入修复。

技术选择与衔接：沿用唯一 workspaceStore 及现有 mountEpoch、submitSequence、busyRef、busy，不新增全局代际或认证管理器。利用现有 useLayoutEffect 生命周期安装 workspaceStore.subscribe 监听，直接观察唯一 generation 的变化。store 的 publish 先替换 state，再同步调用 listeners，因此监听可以在 React 批量渲染完成前同步失效 sequence、释放 busyRef；setBusy(false) 负责下次 React 展示。不同订阅者通知顺序不作为正确性前提，回调仅读取最新 getSnapshot。

允许产品文件仅 `web/src/pages/Login.tsx`，回归仅 `web/src/pages/Login.test.tsx`；另允许本轮计划、审查报告和证据。不得修改 auth/client/store/API、Dialog、依赖、App 路由、后端或 Task10。主会话最终维护 README、账本和明确文件本地提交；实现者不提交 Git。

## 第二层：子模块概述

### 1. Login 生命周期与 generation 订阅

现有布局 effect 负责 alive/mountEpoch 和卸载票据失效，本轮在同一生命周期内安装账号代际订阅。每次 effect setup 从 getSnapshot 捕获该监听已观察的 generation；回调发现代际未变时立即返回，避免普通工作区更新打断登录。代际变化时先更新已观察值，再在当前 mount 仍有效的条件下递增 submitSequence、同步置 busyRef=false、请求 busy=false，并清除属于旧提交的错误。回调不写认证、不导航、不触发新请求。

cleanup 必须解除该次订阅，再按现有 mount 守卫置 alive=false、递增 mountEpoch/submitSequence；同步清 busyRef，保证 StrictMode setup→cleanup→setup 不继承旧提交锁。不得在真实卸载后 setState。每次 setup 捕获自己的 mount，旧监听不能作用于新 mount。

### 2. 提交票据与成功路径

submit 保留同步 busyRef 防双提交、现有 mount/sequence/generation 票据及 current() 全条件。外部身份变化时订阅已先失效 sequence，旧 Promise 续体继续按原 current() 丢弃，不通过放宽 finally 恢复忙态。

正常自有登录成功仍先结束自身 busy/error，然后同步调用 login，再 navigate('/chat')。自有 login 引发 generation 通知时，订阅只重复本地失效/清忙，不撤销认证、不抛错、不阻止已经通过 current() 的本次同步 navigate。不能在 login 之后新增 current() 检查，否则会错误拒绝正常导航。

### 3. 回归验证

使用现有真实 Provider/MemoryRouter/StrictMode 测试框架及 deferred fetch，不 mock generation/current/busy。建立当前受保护请求 401 换代路径；同时保留认证端点 401 不清代际的既有行为。新增测试只验证真实行为，不为监听实现方式编写镜像断言。
