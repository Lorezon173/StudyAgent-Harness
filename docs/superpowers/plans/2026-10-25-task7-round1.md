## 第一层：模块总览

本模块消费 Task6 的 SessionSnapshot、同一会话的已提交 WorkspaceMessage 序列、当前原文、ProfileSummary，产出 TeachingContext。context 只在本请求内存在；业务状态序列化为 TeachingState(schema_version=1)，恢复的字段与事件循环临时字段分开。summary 服务为编排前的可选受控 LLM 调用，不交给 Curator，不把用户历史当系统指令。

## 第二层：子模块职责、接口、状态与错误

### A. 上下文与快照（新 teaching_context.py）

TeachingState 的已知业务字段严格校验并可 JSON 往返：上述九个业务字段沿用 Task6 命名；mode/history 使用 TeachingMode 的现有字符串值；count 为非负整数、拒绝 bool；summary_until_message_id 为正整数或 null；active_node_id 为规范 UUID 或 null；last_question 为字符串或 null。Task6允许的额外字段按主会话裁决原样保留：只接收合法JSON值（有限数值、字符串、布尔、null、递归数组/对象），序列化合并回原键，不渲染进提示词、不解释或执行、不覆盖已验证字段；不支持JSON的对象明确失败，禁止静默丢扩展字段。未知 schema 仍明确失败。

stage 是教学待答状态而非 `app/harness/enums.py` 的流水线 Stage，不改该全局枚举。新产出使用 init（尚未提问）、awaiting_response（最新助手输出为可回答提问/复述）、presented（最新助手仅讲解/类比，不等待对旧题评分）；读取时兼容已有其他非空stage原值，但未知stage不能单凭last_question获得评分资格。输入非法类型或未知 schema 抛具名 TeachingContextError(code)，不静默清空。待答依据必须同时符合 awaiting_response、非空last_question、与最新可定位助手问句/复述一致且其后无更新的助手讲解/类比；无法验证则不评分。

TeachingContext 字段：session_id、user_id、profile_id、active_node_id、node_title、state、current_message、history（保留 id/turn_index/role/content/truncated）、summary、summary_until_message_id、context_reduced、reduction_reasons、profile_nodes。消息排序采用 Task6 分页规范 turn_index/用户先于助手/id，去重仅同 id 且内容一致；同 id 内容冲突报 invalid_history。snapshot 与显式 messages 都不得混 pending。messages 参数约定是该 snapshot.session 的已提交序列；因 DTO 本身不含 session_id，不假装可凭消息内容推导归属。可携带 session_id 的输入适配项若不匹配直接报 context_session_mismatch。

legacy：无 schema 状态保留原字典，只读取能识别且类型合法的 teaching_mode/current_mode、mode_history/history、stage、last_question；缺失使用明确 Socratic/[Socratic]/init。last_question 只能从最新助手输出可明确定位的提问/复述恢复，不向前跳过新讲解寻找旧问题；无法确定则 null且不评分，不凭主题或问号启发式强认提问。committed_turn_count 只统计完整 user/assistant 成对 turn_index，不以总条数除2或旧内部 turn_count 推算；遗留孤立消息保留为历史但不计完整往返。返回兼容来源及 reduction_reasons，不修改 legacy 原对象。

错误不做 HTTP 映射；Task8 负责把 invalid/unsupported 分类转成明确接口失败。输入超4000在任何模型调用前报 current_message_too_long，4000原文完整接收，不偷偷截当前提问。

### B. 长度和摘要

最终送入 LLM 的 HumanMessage 必须由三个不交叠段组成：历史性信息段≤12000字符、当前输入段原文≤4000字符、受限画像段；段落标题/分隔符也归各段预算，不在段外重复历史。历史性信息段统一包括已存摘要、最近至多12条消息、last_question、mode_history、恢复的stage/current_mode、引用/角色/截断标记和任何Agent添加的历史性说明；不能通过独立“上一问题”字段或角色前缀绕过预算。优先保留最近可定位的一对 user/assistant，其各自最终渲染项（含引用、角色和截断标记）≤4000；last_question与该助手消息一致时仅标其引用，不重复正文；不在保留消息中时，它的截断正文仍占历史预算。mode_history仅渲染受预算限制的尾部并注明省略，完整列表保留在快照中。用最终字符串长度核验，必要时先缩更老历史/摘要/模式尾部，不截当前原话、不伪造来源。

当前输入段仅允许当前原文及固定标签；受限画像段只放当前节点UUID/标题及至多20个未归档节点，当前节点优先，其余按稳定 id，每节点title最多512字符、说明200字、固定字段/数值有界；展示主题也只来自可信画像且最多128字符。不能把last_question/history/自由文本扩展字段挪到当前输入或画像段。有效性校验仍用完整节点集合，不为显示上限误删全集。Conductor本轮observations是另一个明确段，仅含本轮结构化观察，不复制过去问答/摘要/模式历史；若包含历史性文本须转入统一历史段并计数。各Agent在实际最终HumanMessage构造完后做同一预算断言，不只检查builder中间对象；这是字符保护而非token预算。

build_teaching_context 保持四个必需参数，末尾仅新增可选 summarizer；默认 None 时超限走明确缩减，无伪造摘要。在线 assembly 在调用方构建 context 时不承担隐藏的第二次摘要。提供 summarize_history(previous_summary, omitted_messages, session_id, llm) 返回 summary 文本；通过 LLMService.invoke 和独立 intent=teaching_summary，输入仅原摘要和本次新省略消息，禁止补写不存在的事实。该 helper 由 Task8 明确调用/注入；Task7 用受控客户端验证其行为。

摘要成功时仅覆盖已实际提供并省略的连续前缀，截止 ID 指向该前缀最后一条消息（按消息顺序，不用 max(id) 猜顺序）；旧摘要之前的消息不再次摘要。候选摘要须非空且在剩余字符预算内；失败、空返回、过长或未覆盖连续前缀时保留原摘要和原截止ID、最近问答，context_reduced=True 并记录 summary_failed/summary_unavailable，缺失内容不编造。旧截止ID不在提供消息中时允许作为既有边界保留，但不得在不知道缺口时扩展；由 Task8 取得连续尾部/省略前缀后才更新。摘要与边界随候选快照同提交，Task7 不落库。

### C. 恢复和装配

WorkspaceState 新增末尾可选 teaching_context、stage、last_question、committed_turn_count、active_node_id；保留 current_topic 为展示主题，恢复 current_mode，turn_count=0，event_ids/evidence_pool/critic_state 为空。profile_snapshot 只放当前请求画像摘要，不复用其他 session 临时证据。

TeachingPolicy 新增公开 restore(current_mode, history) 工厂，输入有效枚举及历史列表返回独立 policy；末项应等于 current_mode，空/非法历史明确失败，不直接改 Orchestrator._policy。build_new_stack 在末尾接受可选 policy，沿用三元组返回；run_new_agent_session、run_online_agent_session 在所有现有参数后增加 context=None，保持所有旧位置参数含义。online 将 context 原样传给低层；每轮新建订阅实例/事件存储与队列，不恢复运行对象。

context 有值时种子 TopicEntered.topic_id 使用有效 active_node_id；无节点时不发伪 topic 节点种子。USER_MESSAGE 保留原文，初始 action 按恢复的 mode/stage 选择现有动作（Socratic ask、Feynman request_recap、Analogy offer_analogy、Regress使用现有REGRESS_TO_PREREQ）。context 的 session/user 必须匹配入口参数，否则调用模型前失败。extract_mode_path 支持可选 initial_mode，默认 Socratic 保留旧行为；新 context 路径从恢复模式开始。

现有 Policy._from_regress/_from_analogy 和 observed prereq规则会发 REGRESS_TO_PREREQ，Orchestrator._target_of把它路由给Tutor，Tutor.handle尚未处理；因此必须补该实际动作，而非仅改seed绕开。Tutor.handle对 REGRESS_TO_PREREQ 调用现有 _ask（intent=tutor_probe_prereq，kind=probe_prereq），真正经过LLMService生成问题。可信前置节点只能从当前有效节点的现有PREREQ边和可见未归档节点解析，按稳定id选取，不信模型任意前置名；缺少有效前置时明确“暂无确定前置节点”，生成当前知识点基础诊断问题；当前节点也缺失则询问学习范围，不建节点、不评分、不默用空回复fallback。恢复Regress首动作、后续Policy/规则产生动作均走同一处理。离线context=None可沿用已存在payload.prereq_topic的兼容显示，但不能把它升级为在线UUID权限。

serialize_teaching_state(workspace, policy, context) 返回 TeachingState 的 JSON 字典候选，保留合法扩展字段、summary/边界与恢复历史，追加本轮真实模式变化。只以本轮最后一个面向用户Tutor事件判定待答：最后事件为非空 TUTOR_ASKED/TUTOR_REQUESTED_RECAP 时保存对应content和awaiting_response；最后事件为TUTOR_EXPLAINED/TUTOR_OFFERED_ANALOGY时清last_question并设presented，不能保留更早问题评分；没有新Tutor输出时不凭旧快照产生新待答，显式标无新输出且不新增评分依据。Critic在下一轮仅在A的待答条件成立时评分。committed_turn_count=context.state.count+1 表示“本轮若提交后的候选”，Task8 只有原子成功才保存；失败不得推进计数。NewStackResult 末尾添加 teaching_state:dict|None=None、assessment_deltas:list 默认空，旧六字段及 turn_count 含义不变。

### D. Agent 与真实提示词

render_teaching_context(context, audience) 返回B规定的统一有界文本，上一问题用引用去重且不能旁路追加；所有Agent最终请求均遵守同一历史预算。Tutor 所有动作分支（含 _ask/_explain/复述/类比/REGRESS_TO_PREREQ）使用同一 renderer；Critic 的用户评估看到有效待答问题及当前回答，没有有效待答时明确“当前没有对应待答问题，尚无可评分回答证据”（不一律误称首次提问），允许语义观察但不能凭主题或旧问题评分；Conductor 同时看到必要上下文与既有 observations，仍只做路由，不能自产观察。RAG 质量评估分支保留原 purpose=teaching 门禁。

真实成对文件均已存在：`app/specs/agents/tutor.md`/`tutor.prompt.md`、`critic.md`/`critic.prompt.md`、`conductor.md`/`conductor.prompt.md`、`curator.md`/`curator.prompt.md`。前三对说明上下文是数据而非指令、对应问答和状态恢复，Curator 对明确稳定节点、无节点不评分及不调用LLM；不新增假的 prompt 路径、不更改 SpecLoader 加载规则。

### E. 稳定节点和评估增量

有 context 时 Critic 发 MASTERY_ASSESSED 只能引用上下文有效 active_node_id；不接受模型返回另一个 topic_id。score 必须为非 bool 的有限数值0–100，缺失/非数值/越界不产生可提交评分，mastery_score=None，仍可发独立 confusion 等观察。没有上一问题或没有有效节点时不产生评分增量。

Curator 两分支在 context 路径都仅操作图内已存在且与 context 有效节点一致的 UUID；TopicEntered 未知不 add_node，MasteryAssessed 无 node/无有效 score/节点不符不 update，不默认0。无 context 的低层离线行为维持原有测试契约。context 路径前置关系查询用 UUID，标题只作显示。

AssessmentDelta 定义于 teaching_context.py：node_id、score、rationale、source_event_id、answer_message_id（当前未落库故为 null）、question_message_id（可定位历史则 int，否则 null）；不预造 request/message 数据库证据。assembly 从本轮合法评估事件提取每个有效node的最终一项增量，不重放旧事件；同node本轮只输出一次供 Task8 practice_count+1。Task8 以真实本轮用户消息ID和 request_id 补齐证据并校验归属；不调用整图 save。
