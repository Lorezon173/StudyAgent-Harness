## 任务 3：CI 与交付配置（独立实施子代理）

文件归属：.github/workflows、docker-compose.yml、生产 Compose 配置、必要部署脚本、.env.example、pyproject.toml/uv.lock（只有实际需要且可重新锁定时），工程回归测试。不得写任务 2 的文件。

输入：main/PR SHA、锁文件、专用 PG 服务、明确的部署环境与 GHCR digest。输出：软件检查结果、镜像摘要、发布记录；环境 secret 的值由运行时注入，不在仓库里虚构。

关键状态：后端/前端/PG/镜像 job 必须分别成功；发布只来自受信 main 且依赖同提交检查，PR 无发布权限；部署串行并显式选择 staging/production；未知服务器配置不触发真实部署。

- [ ] 固定工具策略并使用 locked 安装；前端 npm ci 后 test/build；现有后端测试及 lint 不以扩大 skip/ignore 冒充成功。
- [ ] 使用独立 PG 执行正式迁移并测试登录、会话保存/读取及权限；注入模型替身，不使用付费模型或真实书籍。
- [ ] PR 验证真实 Dockerfile；main 在必需检查成功后构建/推送镜像并记录 digest；显式禁用旧 Release 绕过路径。
- [ ] 本地 Compose 与服务器消费发布镜像的配置分开；生产 JWT/DB 凭据必须显式配置。
- [ ] 提供单服务器部署、就绪冒烟和上一兼容镜像恢复的可运行入口；未配置环境时明确拒绝，不猜测服务器地址。
- [ ] 工作流超时、并发和必要报告留存；文档说明运行命令、secrets/variables 名称、回退与 schema 兼容限制。
- [ ] 本地可运行的检查先验证；Docker/远端不可用时保留未验证状态，不能称整条 CD 已验收。
