## 第二层：子模块契约、数据流与错误



### A. DTO、归属、兼容入口



ChatRequest：message 必填严格字符串、最长4000，原始文本不 strip/Unicode 改写；session_id 保留服务端默认生成，非空最长64；user_id 保留可选兼容但始终忽略。新增 request_id 可选非空最长64（缺省服务端 UUID，不承诺缺 id 的重发幂等）；profile_id 可选规范 UUID；expected_state_version 可选严格非 bool 非负整数。active node 不接受请求任意覆盖，来自 session 的有效节点；选点只走已有 active-node PATCH。空白 message 是否拒绝沿用旧基本契约，不擅加产品限制。



新客户端带 request_id/expected_state_version；旧客户端不带版本时服务端在领取事务捕获当前版本写入 immutable base。session 已存在先验证 JWT owner；NULL/其他 owner 403，绝不能写。profile 参数若提供必须本人且与 session 一致，不一致409 profile_context_mismatch，不自动换绑；不存在画像404。本人旧 session 若 profile=NULL：409 legacy_session_unbound，要求先执行已有迁移/整理，绝不在 chat 自动绑定。本人已绑定 legacy session 正常走 schema1/legacy context。



新 session 不存在：有 profile_id 则校验后按该画像创建；未提供则优先本人唯一 kind=legacy 画像，不存在时创建本人唯一 legacy/default 容器（名称“历史待整理”，kind=legacy，遵守现有唯一索引，竞争失败 rollback 后重读）；创建本人的新 session，不修改任何旧会话。默认容器不复制旧 mastery 数据、不伪造证据；可无 active node，因此聊天不评分。session_id 沿用请求给定值，父先 flush，不能调用会生成另一 id 的 SessionService.create 后丢弃客户端 id。该兼容选择实现为服务局部 helper，不扩展全局默认画像设置。



ChatResponse 旧字段保留，mastery_score 允许有限浮点以不截断 Task7 分数；新增可选 request_id/state_version/profile_revision/active_node_id/status/attempt/error_code/context_reduced/reduction_reasons。成功 persisted=true；运行中或失败返回真实状态 persisted=false、reply统一为空字符串，未提交生成内容不得作为助手回复返回；不制造202成功内容。HTTP 普通状态响应200仅表示状态被读取，客户端必须检查 status/persisted；格式422、JWT401、归属403、缺失404、状态竞争409、composition503，生成/提交故障返回可读 failed 与 persisted=false。SSE 一旦流开始无法改 HTTP 状态，统一 error 投影包含 code/error_code/message/retryable/request_id/status/attempt/persisted=false；final 只代表已提交成功。



### B. immutable payload 与 claim/retry



标准 payload 精确四字段 message/profile_id/active_node_id/base_state_version；使用规范 UUID、小写规范值、确定 key 排序、无多余分隔的 UTF-8 JSON、禁止 NaN，SHA256 十六进制为 hash。文本原样，user_id 来自 JWT 不放受控正文；session/request 在复合身份键。hash 与 JSON 都对比，不只信 hash。



已存在同 id：用保存 payload 的 base/profile/node 填补旧客户端省略项；显式提供版本/profile 必须与保存值一致，message 原样比较；先比 payload 再返回保存的真实状态。不能拿新 state 重新构造旧请求。completed 反序列化 response_json，不调用模型；running 未过期返回 running；过期先短事务 interrupt 并提交再返回 interrupted；failed/interrupted 普通重发只读，不 retry。其他 request 占用过期时也先恢复清占用，再重新验当前 state 并领取，未过期 session_busy。



显式 retry_turn 签名沿用 Task6：user_id/session_id/request_id/expected_attempt/expected_state_version。服务重新锁 session 校验 owner、base/current version、无占用、failed/interrupted、attempt；ChatRequestStore.retry 提升 attempt，完全沿用保存原 payload/hash/base，不收新原文。interrupt 本身也会提升 attempt 来即时废止旧线程；因此失败→retry 可见 attempt 跳两次是现有栅栏契约，不改成回退旧值。



### C. 加载、真实摘要与同步生成



领取提交结束后，另短事务 SessionService.load_snapshot（session读锁→profile读锁）并 load_messages 无分页取完整历史；同事务 ProfileMasteryStore.load_nodes/load_edges 构造独立内存图，只保留有效未归档节点及有效边。snapshot/version/claim 不一致409并转失败管理，pending 原文与 draft 永不加入历史。消息按 turn_index/role/id 排序，由 Task7 helper 校验引用；全量加载证明连续范围，不把50条当全集。



释放所有 AsyncSession/连接/锁后，线程内以真实 `app.infrastructure.llm.LLMService` 实例闭包调用 summarize_history(previous_summary, omitted_messages, session_id, llm)，注入 build_teaching_context，随后 run_online_agent_session(..., graph=graph, on_event=callback, context=context)。只在线程中持纯数据，graph 不再调用已关闭 DB store；不调用 graph.save。摘要也计入300秒总预算及续租。摘要失败由 Task7 现有 helper 保留旧边界并标缩减；不换 FakeLLM，不提前持久化。schema未知/非法、context_session/message/graph_context_mismatch 保留明确错误，不降级为无 context 重跑。



### D. 执行生命周期与 SSE



每 acquired claim 建 Execution（user/session/request/attempt、monotonic started/deadline、生成 task、订阅队列），key 包含 attempt；内存仅帮助订阅、取消与应用关闭，不代表持久化队列。30秒调度一次短事务 renew，180秒 lease；总300秒从 claim acquired 开始，摘要包含在内，deadline 后先 interrupt 原 attempt 并提交再弃结果。续租失败 fail closed，不允许不知租约归属仍提交。



断开 HTTP/SSE：关闭该订阅拥有的生成执行与事件入口，尝试独立短管理事务标interrupted、提升栅栏、释放占用；线程可能继续运行，不冒称已停止。断连与最终提交按session行锁下的真实状态转换顺序线性化：中断事务先获得锁并提交则旧attempt最终提交拒绝；业务提交先获得锁或数据库commit已发出，则可能实际完成，取消不能撤销已经发出的提交。提交结果未知先新连接读取completed/response，不覆盖成功；未完成才尝试比较原attempt中断。客户端通过status或同id重发读取最终真实结果，网络断连墙钟不是事务胜负依据。取消期间屏蔽必要的管理清理取消，清理失败则租约过期恢复。服务关闭同样 best effort interrupt，强制进程退出靠过期恢复。重复 running 的订阅不拥有执行权，不应因它断开而取消原任务。



SSE project_event 保持旧事件字段，callback 通过 loop.call_soon_threadsafe 投递，断开后不继续积累队列；completed 重放只发送已有 final，running/failed/interrupted 返回状态事件（失败用 error），绝不再次生成。无 durable replay 事件日志承诺，仅最终 response 可重放。生成和最终提交异常均 error，不能发送 final persisted=false 冒充成功。



### E. 原子提交与画像增量



commit_turn 新内部输入 identity/claim/snapshot base/result，返回 CommitResult(turn_index,state_version,profile_revision,request_id,response)。调用方拥有独立最终事务；先 session 写锁并验证 owner/profile/base/active_request，再检 request attempt/status/lease，随后锁 profile 最新 revision，再校验 node 未归档且属于该画像。管理续租/interrupt 也先 session，profile 手动变更不反向锁 session，防止锁序环。



不以旧 snapshot.profile_revision 作为增量 CAS 输入：锁最新 profile 后串行应用本轮真实 delta，同节点按提交顺序更新 score/rationale/last_practiced_at，practice_count 由数据库当前值+1，node revision+1；一次非空 delta 批次 profile revision+1，空批次不虚增画像 revision，仍返回当前 revision。只更新本轮 node，无其他节点/边重写。唯一 evidence(user/session/request/node) 兜底防重复；重复 evidence 不得先+1再吞冲突，重复提交首先由 request completed 拦住；异常全部 rollback。



先 flush 父 session/request（新 session 在 claim 已提交也必须保证顺序），用当前 next_turn_index 添加 user/assistant 两条，flush 得真实 user message id；逐项校验 AssessmentDelta 的合法 score、有效 node、历史 question id 属于本 session 且对应待答问题；answer_message_id 仅允许 null 或本轮新 user id，然后以新 id 补齐 evidence。source_event_id 保持候选校验/日志，不滥增 schema 字段。候选 schema1 以 Task7 parse/序列化约束验证，count 恰好原 committed+1，active与session一致，合法扩展保留；不得保存{}。



同事务写 evidence/delta、session.state_json/state_version+1/next_turn_index+1、清 active_request、完整 ChatResponse JSON 与 request.completed；ChatRequestStore.complete 仍先通过原 attempt/running/lease 校验，不先手动清 active 导致检查失败。所有步骤只一次最终 commit；commit 成功后才发 final/返回 persisted=true；response_json 中存的即成功响应，可跨进程重放。失败 rollback 全部业务，再独立事务 interrupt(status=failed,error_code=...)，只允许匹配原 attempt/running 才改，不能覆盖 completed/新 attempt；响应 persisted=false。若 commit 抛错且结果是否提交不明，先新连接查询 request.completed 并据真实 response 重放，不能直接覆盖成 failed。



### F. DirtyFlag 及兼容包装



DirtyFlag 保留原 user_id/ttl 位置参数，在末尾 keyword-only profile_id=None，内部 key=(user_id,profile_id)，None 仅代表旧用户级 key，不是通配符。mark/is/clear 同作用域，清某画像不清其他画像或旧用户级 key。新路径每次加载真实 DB，不依赖内存缓存保证正确性；失败标本画像，成功提交后清本画像。旧 persist_turn 返回 int/None、owner403传播、父 flush/业务一次 commit/rollback 保留；workspace 新路径使用turn_commit.commit_turn，不经旧graph.save/state={}。legacy核心在任何session save、message add、graph.save前必须先owner核验，再检测现存profile_id非NULL或state JSON含schema_version键的workspace会话：安全返回None，零业务commit、零业务修改，不触碰传入graph；坏JSON返回None不重置。先owner后检测使异主/NULL owner仍403。旧无profile且无schema键的legacy会话保留int/None、父flush、一次commit、全rollback行为；不靠新route不调用保证安全。

### HTTP/SSE预检、订阅与断开通知的具体接口



- Service公开prepare_request(user_id,request)→PreparedTurn：完成owner/profile/version/同id payload校验、过期恢复及claim管理提交，返回纯数据；这些403/409必须在StreamingResponse创建/发响应头前抛出。run_claim(prepared, *, on_event=None, disconnect_event=None)→ChatResponse只消费已准备claim，不再claim；submit_turn(user_id,request, *, on_event=None, disconnect_event=None)依次调用prepare_request/run_claim。retry_turn同样返回已领取PreparedTurn再调用run_claim，不引入第二状态机。

- SSE handler先取得JWT及真实Request，创建queue、线程安全callback关闭标志和disconnect_event，再await prepare_request。已完成/未acquired状态只投影保存结果/真实状态，无runner。对acquired的PreparedTurn，handler返回本文件私有PreparedTurnStreamingResponse（StreamingResponse最小子类），该响应的__call__以try/finally包裹父ASGI调用；finally关闭投递并await asyncio.shield(service.cancel_owned(prepared,reason='client_disconnected'))。generator内部也有finally执行同一幂等释放；cancel_owned只处理中断仍匹配的owned attempt，completed/未acquired不改。这样首次yield前ASGI disconnect或生成异常也会进入响应层finally，而不是依赖generator是否已经启动；handler在prepare完成后到返回响应间取消也捕获CancelledError并同样清理。不是只挂一个可能不运行的BackgroundTask。

- generator在queue和callback已建立之后启动run_claim(prepared)，仅负责消费project_event并在确认成功后发final；不得在generator里再次submit_turn/prepare/claim。响应父类的可信ASGI断连监听触发取消，响应层finally将通知传给Service；回调按原关闭标志安全弃置。若进程在handler返回响应与响应ASGI调用间强制退出，不能保证finally执行，依靠已保存租约过期恢复，不承诺耐久队列。

- HTTP handler接受FastAPI Request。在JWT与解析后，建立disconnect_event，启动局部watch_disconnect(request,event)与submit_turn；watch使用真实Request.is_disconnected读取ASGI通知，并通过asyncio事件/有界wait_for间隔最多100ms再观察（不是命令sleep），检测到断开置event通知Service。不能假定handler自动收到CancelledError，也不能让watch与JSON解析竞争接收body：必须在Pydantic已解析后启动，且只由该watch读取disconnect。submit_turn完成finally取消/await watcher，防泄漏。run_claim在生成、续租与最终提交前/结果未知处理期间观察event并执行前述行锁线性化中断；异步取消to_thread从不等于线程停止。

- cancel_owned(prepared,reason)→真实Claim或保存完成响应，只在acquired=true且原attempt仍running时尝试独立session锁管理事务；多处finally幂等，不能二次attempt递增或覆盖新retry。网络断开后不能实际发送响应，但管理结果必须可由GET/同id重发读取。watcher/响应finally只通知取消，真正DB状态仍由Service统一处理，API不直接写Store。

- 新增真实ASGI接线断言：SSE异主403、payload/version409发生http.response.start之前且runner零调用；首yield前立即发http.disconnect、生成尚未启动/刚启动两种屏障均最终interrupted并释放占用；重复running订阅首yield前断开不取消原执行。HTTP通过真实ASGI http.disconnect而非直接cancel handler触发watch，阻塞runner后断开→Service接通知、真实DB中断；另对提交先持锁场景断开→可能completed且可读。事件队列与callback建立必须早于runner调用，旧线程晚到无队列泄漏/无DB写。使用现有HTTP/SSE测试路径补断言，不假设测试客户端自动模拟断开。

## v1.4 知识点切换的待答归属门禁

模块目标：保证真实评估仅归属当前知识点的对应问题。来源为已批准raw的当前知识点问答约束；不增加schema、不修改Task7 Agent/prompt。
