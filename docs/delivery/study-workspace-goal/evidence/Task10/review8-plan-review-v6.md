## 阻断：旧实现不存在计划中新建的 IndexedDB 事务

计划第八节要求“在真实 UI 上先建立业务 RED”，并列举真实 IndexedDB 事务进行中 abort、事务 complete 后发布前换代等时序；而当前待修源码没有本轮拟新增的关联 checkpoint IndexedDB 接口，旧实现无法产生该事务。把模块不存在、编译失败或人为制造的旧版事务当成业务 RED，不能证明实际问题；只执行新代码后的事务测试又不满足当前文字所写的旧版步骤。

**修订要求：** 分别列出旧版可由真实页面复现的业务失败（例如已存在的旧成功覆盖新冲突、长历史恢复行为）及记录方法；对仅随新存储模块产生的事务中止、提交后失效、崩溃恢复等能力，明确先写可执行的行为测试并记录新能力尚不存在的事实，再在存储接口具备真实事务后运行真实浏览器与可控适配器测试，不能将“模块不存在”伪报为既有产品业务缺陷。保留事务前、进行中、complete 后发布前、结果未知和重启的全部安全断言及原始证据。

## 已核查的主要修订

- 已明确事务前核身份，进行中观察到失效则尽力 abort，提交或结果未知的旧数据不得由旧操作发布；同用户重新认证须重新核验，其他账号不展示或续用，清理限定完整命名空间，不把 IDB、认证或网络伪装成同一事务。
- 已改为后端支持的每页 50 条，有限批次自动公平续读，允许暂停；计划要求统计 10,050 条的消息页请求、身份重验和点击次数，以及 UI 响应与另一个请求的公平性。不承诺单响应固定字节、物理 8 秒完成或无限浏览器存储。
- 保留当前代次有效 401 必须使认证失效、换代后的旧 401 不影响新账号；逻辑停止不声称物理取消 fetch，旧在途请求仍计并发额度。
- 每 checkpoint 的隔离、两个并发关联、排队与 writer/source 验证、重复 ID 分类、opaque cursor、恢复前重新核验与不宣称跨 HTTP 原子性仍在计划范围；真实浏览器和模拟适配器需分别记录。

以上是静态计划检查，尚不能证明这些复杂并发和崩溃保护已经实现。修订测试顺序后请再次独立复审；全量回归、完整代码复审与真实验收仍不能省略。
