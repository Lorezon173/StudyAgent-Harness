## 阻断：同 ID 未观察到权威记录不等于没有其他调用

raw 第 79、84、89 行允许收到当前调用的结构化 `session_busy`，且当前没有已接纳的同 ID 权威记录或身份冲突时，将本 writer 副本排除发送门禁；它同时承认该证据只证明**此调用**被拒绝，不能证明该 ID 在全系统不存在。计划第 89 行测试同 ID **已有** running/终态或副本冲突，但未要求发现未被本客户端观察到的另一调用。

可核对的交错是：本调用收到 busy；另一个客户端随后使用相同 ID 提交并完成；本客户端只收到之后的空闲 snapshot。`app/orchestration/session_service.py:208-215` 的 snapshot 只包含非 completed 请求，因此不会报告该完成记录；本地“没有已接纳权威终态”和空闲 snapshot 均不能证明它不存在。若按 raw 第 84 行以新 ID 发送原文，可能重复提问。该情形不需要假设本次 busy 本身错误，问题在于该响应不能证明其他调用未领取。

须明确恢复前如何核查原 ID 与其他已知 writer/副本，以及核查和实际新发送间同 ID 并发的边界。至少测试另一个客户端在 busy 后以相同 ID 完成、空闲 snapshot 不含该请求的交错，确认不会以新 ID 重发；权威记录必须校验身份、payload、attempt 与基线并按已有完成关联流程处理。若现有协议不能保证排除后续同 ID 并发，应说明不能证明的边界并设计保守处理，不以 404 或“没有观察到”当作全局不存在。不得以篡改后端契约或删除副本绕过。
