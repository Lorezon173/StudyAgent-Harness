## 覆盖检查

- 桥接失败：计划要求临时页不发布，保留旧消息、历史 ID、cursor、visited 和上翻状态，错误可见并可重新同步；重试必须真正接通连续链。覆盖网络错误、中途失败、游标回环及消息冲突。
- 独立字段：先核对账号、会话和画像归属；画像按 revision 单调接纳并提示同版本冲突，教学按既有版本处理，活动按 epoch 与观察序号处理。有效 running 必须保护发送门禁并进入已有查询或轮询；过期 idle 不得覆盖较新活动。
- 未关联继续：失败不能标记继续或 matched、清除副本或解除活动门禁；独立画像与活动处理仍受账号、请求、attempt 和观察身份约束。测试包含成功重试及账号/较新请求交错。
- 迟到错误与账号：测试计划覆盖较新 load 或活动观察先完成、换账号和并发上翻，旧错误及结果不能覆盖新状态；无旧会话时历史失败不得显示为完整加载。
- POST 后旧 GET：计划正确将其列为待证实假设，要求真实路由与延迟网络先验证，失败须定位于业务表现；若未复现不得编造 RED 或添加猜测性修复。若复现，限定原请求重查、不重复 POST、保留副本、校验 attempt/消息并避免无限立即重试。
- 回归与交付：明确旧存储、跨 writer、路由、活动门禁回归，冻结源码前后哈希，全量测试和构建后再做全范围独立代码审查与真实验收。

实施时需特别确认：桥接 401 会按现有 API 认证失效路径换代，旧快照及错误不能在换代后发布；旧活动观察失效不能把其 running 或 idle 当作当前权威状态。计划的账号换代和旧观察测试应实际覆盖这些边界，若发现现有设计无法满足则先补充计划并复审。
