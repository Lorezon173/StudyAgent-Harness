## 阻断：画像摘要归属验证缺少可执行的字段契约及跨会话正例

raw 的 2.2 节要求验证 snapshot 内 session、profile、summary、请求属于同一用户与画像，但 `app/models/workspace_schemas.py` 的 `ProfileSummary` 没有自身 user_id/profile_id；`ProfileEvidence` 也不暴露 user_id/profile_id。节点和边则分别含 profile_id。客户端无法仅凭这个 DTO 对每个摘要及证据独立证明所属用户与画像。

此外 `app/orchestration/profile_service.py:149-168` 按 user/profile 汇总最近证据，包含该画像下的其他 session；`recent_evidence.session_id` 合法地可能不同于当前 session。若把“同一用户与画像”错误落实为证据必须来自当前 session，会破坏用户明确要求的同画像多会话共用学习画像。现有任务 3 未明确这些字段边界和跨会话合法正例。

**修订要求：** 在 raw 和计划中逐项说明客户端能核验的字段、由认证后端 session/summary 查询和数据库约束承担的归属保证、DTO 未提供字段的不可独立验证边界；按现有字段校验画像节点、边和请求的明确身份，但不得凭缺失字段臆造信息。增加同用户同画像下来自两个 session 的合法 recent_evidence 正例，以及能由现有 DTO 发现的跨画像节点/边和跨用户或跨画像请求异常测试；同时验证空摘要、合法 null 画像及归属校验失败不污染缓存。若实际需要证明服务端没有暴露的字段，先确认协议及授权，不能声称仅由客户端实现已经证明。

## 其他检查

- 继续操作的历史错误与请求错误分别使用历史任务和活动观察身份，覆盖新观察在途/完成、较新 load、换代及有效错误；要求历史失败仍可见，不因旧活动结果覆盖新请求错误。
- 跨画像防御覆盖 p1→p2、p1→null、已有 null→p1、首次无缓存、异常恢复及发送/关联/清理等入口；迁移文件确有对历史 null 画像补绑定，不能将其视为正常运行时自动改绑的证据。
- 计划要求先用真实路由、控制器和受控网络复现静态推导，分别保存真实 RED 或已满足证据，保留历史、草稿、活动锁和 writer 副本。最终有全量回归、源码哈希、独立代码复审与真实验收门禁。
