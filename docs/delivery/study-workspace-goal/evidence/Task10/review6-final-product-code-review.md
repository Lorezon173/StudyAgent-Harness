## Important：较新关联已确认内容冲突，较旧成功仍可解除冲突

位置：`web/src/store/workspaceController.ts:793-814,826-865`，并发入口 `web/src/pages/Chat.tsx:52`。

同一 completed 请求的旧关联正在等待历史页；用户点击重新查询，较新关联先返回当前可信消息冲突，被标记 `inconsistent` 并阻止继续。随后旧关联返回与旧快照匹配的消息：`associationCurrent` 只拒绝从非 matched 状态覆盖新 matched，不拒绝覆盖新 inconsistent；成功分支又不要求本次是最新关联，因而会把记录改回 matched，并调用本人副本清理。该顺序可能用较早证据掩盖较新可证明的矛盾，违反第六轮计划对当前有效冲突必须提示和阻塞的要求。旧成功在较新**网络失败**后可以继续的测试 `review6-reverse.log` 不证明在较新**内容冲突**后也应放行。

这是依据现有 UI、异步调用及状态写入的静态路径推导，**本审查未实际运行该交错**，不能描述为已发生的线上故障。需先用真实 UI 和两个受控消息页复现“新冲突先完成、旧成功后到达”，再区分失败与可信冲突设计安全的发布与重查；不应通过一律屏蔽所有旧成功来破坏已批准的网络失败恢复场景。
