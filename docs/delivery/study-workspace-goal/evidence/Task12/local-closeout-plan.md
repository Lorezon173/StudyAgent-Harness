# Task12 收口与本地提交计划

> 执行顺序为计划独审、Terra 准备、文档与清单独审、主会话本地提交和复核。勾选项用于交接。

## 1. 模块总览

将已通过功能验收的 Task12 从 `VERIFIED_UNCOMMITTED` 推进到可追溯的本地 `DONE`。基线是 `a6117c4`，功能依据为原 [raw](../../../../../superpowers/frontend-ui/2026-11-04-task12-round1-raw.md)、原 [plan](../../../../superpowers/plans/2026-11-04-task12-round1.md) 和 [验收独审](acceptance-audit.md)。浏览器最新运行 25/0/0，包含一组真实 HTTP 账号场景。Web 16 文件 428 项通过且构建成功，沿用独审说明的版本关系。当前 20 项与冻结哈希一致。收口以 Git 工作树和索引分离控制提交范围，功能代码沿用冻结版本。

完成条件是经审查的 Task12 产品与验收材料进入第一笔本地提交，实核通过后另以第二笔本地提交记录 `DONE` 和第一笔的完整 SHA。第二笔也实核通过后进入 Task13。Task11 保持既有结论。Task13 仍按原范围负责真实教学模型、隔离 PostgreSQL 重启持久化及端到端验收。`DEC-SESSION-001` 的 B 扩展是独立候选，账号 B 是本次真实 HTTP 隔离证据。提交范围仅限本地。

## 3. 详细实施计划

- [ ] **独审计划。** 核对基线、验收边界、README 字节保护、索引选择及 `DONE` 时序，审查通过后交由 Terra 准备。验收审计给出 `VERIFIED_UNCOMMITTED`，现有账本仍记 `IN_PROGRESS`、`commit=null`，准备阶段更新验收描述并保留未提交状态，Task13 保持 `PENDING`。
- [ ] **准备验收摘要。** 在 Task12 证据目录形成摘要，链接最终 25/0/0 的运行日志和退出码、428 项与构建日志、20 项冻结哈希、累计独审和原设计。沿用验收独审的 L1–L4 范围，明确受控浏览器、真实 HTTP 偏好、DOM/静态、历史失败与最新通过各自的证据。保留 E2E 独立 TypeScript 检查和联网安全审计的既有限制。TODO 中 B 候选继续独立追溯其原 raw 和 plan。
- [ ] **整理 README 和自有账本。** README 只整理工作树中自有 Task12 EOF 段。修改前后以原前缀的 87830 字节校验 SHA256 `C91DD44F501A4ED370B64FD36E24F7986A3E71F1DC7312C7AE89EA068DEAD70B`，保持用户原有字节、编码和换行。只整理 `TODO.md`、目标目录 `status.json` 和 `progress.md` 的自有内容，待提交记录仍标未提交，避免预写 SHA 或提前标记 `DONE`。
- [ ] **制作路径与差异清单。** 独审计划后逐项列明路径、来源、状态、暂存方式及证据用途。列入冻结的 Task12 源码、原 raw 和 plan、经筛选的验收与审查证据、收口材料以及自有 TODO/status/progress。排除用户 README 原 162 行差异、`docs/asset-inventory.md` 原 34 行差异、任务外文件、凭据和缓存。暂存前保存 README 用户差异的逐行比较基线，以 `a6117c4` 的 README 对工作树原 87830 字节生成差异。`docs/asset-inventory.md` 的实测 SHA256 为 `41462288EB1A53EBF320126A3A77047B9E2242FA497EC951AC8D29701248DE1B`。日志与附件逐项检查，证据路径使用显式文件名单。
- [ ] **独审文档和清单，按清单暂存。** 检查 HEAD、索引和工作树，发现无法归属的现有暂存项或冻结漂移即暂停。README 基于 HEAD 版本构造只增加自有 Task12 段的补丁，先用 `git apply --cached --check` 检查，再只应用至索引。其余经批准的纯 Task12 文件按明确路径暂存，混合文件按已审片段暂存。核对索引差异、空白检查、20 项冻结内容及 README 前缀保护，记录因 Git 换行规则需要分别校验的工作树字节和索引内容。
- [ ] **创建并实核第一笔产品提交。** 索引与审查范围吻合时，以 `a6117c4` 为父提交创建第一笔本地提交。核对实际完整 SHA、父提交、提交文件和 README 片段。确认索引为空，未暂存的 README 用户差异与基线逐行一致，按变更行和顺序比较，区分补丁的行号、上下文及文件元数据；同时复查前缀字节哈希和资产完整 SHA256。发现偏差即暂停并保留工作成果。
